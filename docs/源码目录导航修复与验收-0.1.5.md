# 源码目录导航修复与验收（0.1.5）

日期：2026-10-15。

## 问题与原因

源码模式点击侧栏目录会切换为渲染模式；上下浏览源码时，左侧当前章节高亮不跟随。

原因有三处：

1. `AppShell.handleSelectHeading` 对所有非阅读模式直接执行 `onChangeViewMode("render")`，没有源码定位分支。
2. 当前章节检测只在 `viewMode === "render"` 时监听页面滚动，源码编辑器没有回报自己的阅读位置。
3. 目录标题只有 ID、文字和层级，没有真实源码行号，不能可靠定位重复标题或编辑后移动的标题。

## 实现

- `HeadingItem` 新增 1-based `lineNumber`，解析标题时记录真实源行；相同文字的标题保留不同 ID。围栏按符号与长度配对，避免代码示例中的伪标题进入目录，支持 CRLF 和最多三个空格的 ATX 标题缩进。
- `AppShell` 保留当前模式，向源码编辑器发送 `{ headingId, requestId }`。每次点击递增请求号，重复点击同一项仍可重新定位；请求同时按文件与视图上下文过滤，切换视图不重放旧请求。
- `SourceEditor` 用 CodeMirror 的源码行和行块几何定位，分别滚动实际需要滚动的编辑器容器与页面，不修改文本、光标或选区。长文档虚拟化与软换行造成的估算高度通过有限次数的测量校准。
- 阅读位置取视口与源码容器的可见交集，在 CodeMirror 中映射为源行，再按行号查找当前标题。页面滚动、编辑器内部滚动、尺寸变化和编辑更新均按 animation frame 合并计算；普通滚动回报高亮，不反向定位正文。
- 显式导航期间保护目标章节，定位稳定后记录滚动位置。之后滚动偏离、滚轮、触摸、键盘滚动或编辑会释放保护，避免高亮锁死在旧章节。
- `Sidebar` 按较小标题层级寻找祖先，支持一级直接跳三级的标题；自动展开后重新跟随当前项，隐藏项不参与可见区域测量。跟随只滚动目录列表。

浏览器长文档包含 57 个实际标题、1245 行源码，已通过：

1. 重复标题与围栏内伪标题处理。
2. 点击目录保持源码模式，正确定位虚拟化文档后部。
3. 两个重复标题、重复点击同一项和快速连续导航。
4. 页面与真实鼠标滚轮上下浏览时目录高亮跟随，原有光标不变。
5. 侧栏自动跟随只滚动自身，当前目录项可见，正文不被反向移动。
6. 在标题前插入源码行后，目录重新定位到更新后的源行。
7. 阅读模式目录定位和滚动高亮保持正常。

`npm run lint`、TypeScript 检查和 `npm test` 已通过，单元测试共 7 项；现有 `npm run test:split` 也通过，覆盖双向编辑、公式、快速切换与错误恢复。

## 后续方向

后续可保存各视图在同一文档中的浏览位置，切换视图后恢复到对应章节，并对大文件加入滚动性能记录。当前修复重点是目录定位与阅读进度同步；现有标题目录仍覆盖一至三级 ATX 标题。
