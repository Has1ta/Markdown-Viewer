# 双栏渲染修复与验收（0.1.4）

日期：2026-10-15。

## 问题与原因

切换双栏后，源码正常显示，右侧渲染编辑区域空白。浏览器实际复现的错误为：

```text
Error: You need to enable CodeMirror to use LaTeX feature
```

`RenderEditEditor.tsx` 使用按需 `CrepeBuilder`，加入了 `latex` feature，却没有加入其强制依赖的 `codeMirror` feature。源码侧自己的 CodeMirror 不会为 Crepe 注册代码块插件。因此即使文档没有公式，右侧也会在初始化时抛错。

恢复初始化后，截图还暴露了第二个问题：Crepe 懒加载的 `reset.css` 含有 `.milkdown .ProseMirror { padding: 60px 120px; }`。原项目覆盖规则优先级相同且较早加载，最终被默认样式覆盖，窄一些的双栏中正文被挤成细列。

## 修复

1. 在 `latex` 前启用 `codeMirror`，导入对应代码块 CSS；保留按需 feature 与双栏懒加载架构。
2. 每个 effect 建立独立挂载节点，卸载时先移除该节点，再等创建成功后销毁对应实例。创建失败显示可见提示；不对停留在 `OnCreate` 状态的失败实例执行无限等待的 `destroy()`。
3. 源码同步仍使用 `replaceAll(markdown, true)`。同步保护改为只覆盖该操作，移除固定 250ms 窗口；记录外部同步后的规范化快照，过滤无内容变化的格式整理和替换之前延迟到达的旧回调，避免真实输入被忽略、源码被自动改写或旧内容回写。
4. 将正文规则限定为 `.render-edit-editor .milkdown > .ProseMirror`，使内边距、字号和配色稳定覆盖 Crepe 默认值，也避免影响浮层内的嵌套编辑器。代码、表格和公式在自身容器中横向滚动。
5. Vite 排除 `release/`、`dist-electron/`、`output/` 与 `.playwright-cli/` 的监听，依赖扫描限定 `index.html`。此前监听打包目录在 Windows 产生重命名 `EPERM`，并在监听正在处理的 exe 时以 `EBUSY` 退出。

## 浏览器回归

先启动 Vite 服务或 `npm run dev`，再执行：

```powershell
npm run test:split
```

脚本使用独立 Playwright CLI 会话，不新增 Playwright 项目依赖；通过 Node argv 调用 npm CLI，避免 Windows shell 插值。源码全文从编辑器状态读取，不依赖虚拟滚动区域的可见 DOM 文本。可用 `SPLIT_TEST_URL` 指定其他服务地址。

已验证：

- 内置示例只生成一个右侧编辑器，标题、任务列表、表格、代码块存在；进入双栏不重写源码。
- 源码更新可同步标题、粗体、列表、表格、行内 `$...$` 和块级 `$$...$$` 公式以及代码块。
- 右侧编辑可以回写源码；最终三轮实测 216、219、215ms，符合 Milkdown 内置 200ms 防抖。断言为调度留有容差。
- 源码同步后立即在右侧输入，修改保留；多次快速切换只保留当前实例。
- 1440、1036、390px 视口均无页面级横向溢出；正文左右内边距分别为 32、32、20px。窄屏上下排列。
- 正常流程 `pageerror=0`、`console.error=0`。
- 最终代码连续三轮完整回归通过；每轮额外注入一次缺少 CodeMirror feature 的故障，确认失败提示、源码仍可编辑及撤销故障后恢复。预期的一条初始化错误日志单独核对，未混入正常流程结果。

## 公式语法边界

主阅读视图支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`。双栏 Crepe 当前支持美元定界符，尚未接入主阅读视图的括号定界符扩展。此次修复恢复双栏初始化和现有公式功能，不通过替换字符串改写原文。

后续可为两种渲染器补充统一的公式语法与往返编辑测试，尤其检查代码块中的公式示例不会被误解析。
