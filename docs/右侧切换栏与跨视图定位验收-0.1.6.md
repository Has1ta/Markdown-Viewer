# 右侧切换栏与跨视图定位验收（0.1.6）

日期：2026-10-15。

## 需求与原因

将渲染、源码、双栏按钮常驻右侧，滚动正文时保持可用；从“1.3 表格样式”等章节切换视图后，继续阅读对应区域。

原切换栏处于普通文档流，随正文一起离开视口；切换操作只更新视图模式，没有保存并恢复阅读位置。渲染与源码的排版高度不同，直接复用滚动像素也无法准确对应内容。

## 实现方式

- 桌面采用右侧固定纵排切换栏，并为正文预留空间；窄屏采用右下固定横排，避让返回顶部与提示。方向键跟随纵向或横向布局，配合 `aria-orientation` 和单一 Tab 焦点入口。
- 切换前保存标题 ID、章节内相对进度与是否位于文档顶部；切换后按目标视图的实际布局恢复。没有标题时按全文区间映射。
- 阅读视图使用标题与正文的 DOM 位置；源码视图使用 CodeMirror 行块几何，兼顾软换行、虚拟化估算和编辑器内部滚动，通过有限次重新测量校准。
- 惰性加载期间保留最近一次位置，快速切换时更新请求；源码切走前提交待处理输入，保持 Markdown 字符串为内容来源。
- 页尾标题可能没有足够空间滚到阅读线，捕获位置时保留仍然可见的显式目录目标，避免误判成前一节。

这种映射保持对应章节及相近的章节内阅读区域。不同内容的源码与渲染布局差异较大时，不承诺相同像素或逐行对齐。

## 开发环境验证

启动开发服务后执行：

```powershell
npm run test:views
npm run test:toc
npm run test:split
```

新增 `test:views` 通过 Playwright CLI 独立会话验证，完整回归连续两轮通过：

1. 内置“表格样式”渲染切源码、末尾“代码块”往返及双栏定位。
2. 1440、1036、390px 下切换栏滚动前后矩形位置不变，按钮可点击，没有页面横向溢出。
3. 长文档章节中段 43% 与 72% 位置双向映射，六次检查最大进度误差约 0.03 个百分点。该数字来自测试文档，不代表任意文档都具有同样误差。
4. 渲染、源码、双栏连续与快速切换，最终请求生效，源码逐字不变。
5. 页面异常与控制台错误均为 0。

补充边界检查通过：文档顶部五次往返均保持 `scrollY = 0`；无标题长文档 46% 与 73% 位置往返保持相近全文进度；同一个 JavaScript 任务中写入源码后立即切换渲染，最后输入保留，返回源码后逐字一致；桌面上下方向键和窄屏左右方向键工作正常。

原有 `test:toc` 通过 57 个标题、1245 行源码的导航回归，包含真实滚轮、重复标题、插入行后重定位、侧栏自身跟随和移动目录抽屉。`test:split` 通过双向输入、公式、快速切换、布局和错误恢复；错误恢复用例会主动注入一次预期初始化失败，正常流程无错误。

`npm run lint`、`npm run typecheck`、`npm test` 通过；单元测试为 3 个文件、9 项。
